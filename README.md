# نظام إدارة مكتب المحاماة

نظام ويب متكامل لإدارة القضايا والعملاء والجلسات لمكاتب المحاماة، مبني بـ **Next.js 14** و **Prisma** و **NextAuth**، بواجهة عربية كاملة (RTL).

## المميزات في هذا الإصدار (MVP)

- 🔐 تسجيل دخول بأدوار (شريك / محامي / سكرتير)
- ⚖️ إدارة القضايا: إنشاء، متابعة، تغيير الحالة (مفتوحة/جارية/متوقفة/منتهية)
- 👥 إدارة العملاء (أفراد وشركات) وربطهم بالقضايا
- 📅 إدارة الجلسات لكل قضية + عرض تقويمي للجلسات القادمة والسابقة
- 📝 سجل متابعة (ملاحظات) لكل قضية
- 📊 لوحة تحكم برؤية عامة على نشاط المكتب

## المتطلبات

- Node.js نسخة 18 أو أحدث
- npm (يأتي مع Node.js)

## خطوات التشغيل المحلي

```bash
# 1. تثبيت الحزم
npm install

# 2. إنشاء ملف البيئة
cp .env.example .env

# 3. إنشاء قاعدة البيانات (SQLite - لا يحتاج إعداد خارجي)
npx prisma migrate dev --name init

# 4. تعبئة بيانات تجريبية (مستخدمين، عملاء، قضايا)
npm run prisma:seed

# 5. تشغيل النظام
npm run dev
```

افتح المتصفح على: **http://localhost:3000**

## الانتقال إلى قاعدة بيانات إنتاجية (PostgreSQL / Supabase)

النظام يستخدم SQLite افتراضياً للتشغيل الفوري بدون إعداد. للانتقال إلى Postgres:

1. افتح `prisma/schema.prisma` وغيّر:
   ```prisma
   datasource db {
     provider = "postgresql"
     url      = env("DATABASE_URL")
   }
   ```
2. في ملف `.env`، ضع رابط اتصال Postgres (مثلاً من Supabase):
   ```
   DATABASE_URL="postgresql://user:password@host:5432/dbname"
   ```
3. شغّل:
   ```bash
   npx prisma migrate dev --name init
   npm run prisma:seed
   ```

## هيكل المشروع

```
src/
  app/
    login/              صفحة تسجيل الدخول
    (app)/              الصفحات المحمية (تتطلب تسجيل دخول)
      dashboard/        لوحة التحكم
      cases/            قائمة القضايا + تفاصيل + إضافة
      clients/          قائمة العملاء + تفاصيل + إضافة
      hearings/         تقويم الجلسات
    api/                نقاط API (قضايا، عملاء، جلسات، مصادقة)
  lib/                  إعدادات Prisma و NextAuth
  components/           مكونات مشتركة (الشريط الجانبي...)
prisma/
  schema.prisma         نموذج قاعدة البيانات
  seed.ts               بيانات تجريبية
```

## النشر (Deployment)

يعمل النظام مباشرة على **Vercel** (الأنسب لـ Next.js)، أو أي استضافة تدعم Node.js. عند النشر:
- اربط قاعدة بيانات Postgres حقيقية (Supabase / Neon / Railway) بدل SQLite.
- اضبط متغيرات البيئة `DATABASE_URL` و `NEXTAUTH_SECRET` و `NEXTAUTH_URL` في إعدادات الاستضافة.

## ⚠️ ملاحظة أمنية مهمة قبل الإنتاج

- **غيّر `NEXTAUTH_SECRET`** إلى قيمة عشوائية طويلة وقوية (لا تستخدم القيمة التجريبية في `.env.example`).
- **غيّر كلمات مرور المستخدمين التجريبيين** أو احذفهم قبل الاستخدام الفعلي.
- فعّل HTTPS في بيئة الإنتاج (يتم تلقائياً على Vercel).

## المرحلة القادمة (اقتراحات للتطوير)

بناءً على ما ناقشناه، الخطوات التالية المقترحة:
- 💰 وحدة الفوترة والمدفوعات (ربط بمستخلصات/فواتير لكل قضية)
- 🔑 صلاحيات تفصيلية حسب الدور (مثلاً: السكرتير يرى فقط الجلسات، لا يعدّل القضايا)
- 📎 أرشفة المستندات (رفع ملفات لكل قضية)
- 🔔 تنبيهات بالجلسات القادمة (بريد إلكتروني أو واتساب)
- 🏢 دعم تعدد الفروع
